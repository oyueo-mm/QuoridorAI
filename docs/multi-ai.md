# 다인전 AI (3-A 단계)

정규 4인전과 변형 모드 6종에서 자리마다 **사람 / Random / BFS·Greedy / Max-N** 을 고를 수 있습니다. 구현은 `src/ai/multi/`에 있고, 2인전용 AI(`GameState`, 209개 행동 인코딩, 상태 텐서, Python 학습 인프라)는 건드리지 않았습니다. 정규 2인전은 기존 엔진을 그대로 씁니다.

## Random

합법 행동 전체(말 이동 → 벽 순서)에서 균일하게 하나를 고릅니다. 난수는 `mulberry32(seed)`의 `decisionIndex`번째 값(= 그 자리의 이전 수 개수)이라 같은 상태·시드·순번이면 항상 같은 수이고, 자리마다 시드가 달라 여러 Random AI의 난수열이 서로 영향을 주지 않습니다. 기록에는 합법 행동 수·말/벽 후보 수·난수 값만 남고 점수나 탐색은 만들어 표시하지 않습니다.

## BFS / Greedy (1수 앞)

모든 합법 행동을 적용해 보고 이후 **모든 플레이어의 BFS 최단 거리**로 점수를 매깁니다. "편"(side)은 팀전이면 팀, 아니면 자리 하나이고, 편의 거리는 가장 가까운 말의 거리입니다(팀원 누구든 도착하면 팀이 이김).

```
점수 = −selfDistance·내 거리 − allyDistance·(가장 가까운 아군 거리, 팀전)
       + leaderDistance·(가장 앞선 상대 편의 거리) + opponentDistance·(상대 편 평균 거리)
       − (wallCost + wallScarcity·사용한 벽 비율)           (벽을 둘 때)
       − opponentWinThreat·(다음 수에 도착할 수 있는 상대 편 수)
       + teamWinReady·[아군이 다음 수에 도착 가능]            (팀전)
```

내 목표선에 바로 닿는 수는 `1000`점(승리). 동방향 경주처럼 목표선을 공유해도 거리는 자리별 목표선 기준이라 그대로 동작하고, 상대 즉시 승리 위협은 엔진의 실제 말 이동(점프 포함)으로 확인합니다. 가중치는 모두 고급 설정에서 바꿀 수 있고, 분석 패널에는 후보마다 항목별 기여값과 이동 후 거리가 실제 계산값으로 표시됩니다.

## Max-N

플레이어별 **평가 벡터**를 올려 보내는 탐색입니다. 차례 순서는 규칙의 `turnOrder`를 그대로 쓰며 "좌석 번호 + 1"을 가정하지 않습니다.

- **리프 평가**: 편 t의 강도 `T_t = −(가장 가까운 말의 거리) + wallValue·(남은 벽)`. 자리 s의 효용 = `T_내 편 − (λ·max T_상대 + (1−λ)·mean T_상대)`. 종료 국면은 ±10000(`승리 시 10000 − 수`라서 빠른 승리·늦은 패배가 낫다).
- **개인전**: 각 자리가 자기 효용을 최대화합니다.
- **팀전(2 vs 2)**: 효용을 팀 단위로 정의하므로 같은 팀의 두 자리는 **같은 값**을 갖고, 한 수마다 팀의 값을 최대화합니다. 즉 팀원이 완전히 협력한다고 가정하는 탐색이며, 팀원이 각자에게만 유리한 수를 고를 수 있는 독립 Max-N과 다릅니다. 분석 패널에도 "팀 Max-N"으로 표시됩니다.
- **반복 심화**: 깊이 1(후보 정적 평가)부터 `maxDepth`까지. 시간·노드 예산이 다 되면 끝내지 못한 반복은 버리고 **마지막으로 끝낸 깊이**의 결과를 씁니다. 깊이 1은 항상 끝나므로 합법 행동이 보장됩니다. 노드마다 취소 플래그를 확인합니다.
- **최적화**: 후보 정렬(정적 평가 순), 즉시 승리 우선, "이기는 수를 찾으면 나머지를 건너뛰는" 즉시 가지치기, Zobrist 해시(증분 계산)와 전치표(깊이별 정확값), 중복 국면 재사용. 노드는 "생성해 평가한 국면 수"입니다.
- **벽 후보 축소는 휴리스틱입니다.** 합법 벽 전체가 아니라, 상대 편의 현재 최단 경로를 끊고 실제로 경로를 늘리는 벽만 고른 뒤 평가 순으로 `rootWalls`(첫 수) / `innerWalls`(그 이후)개로 줄입니다. 첫 수 아래에서는 가장 앞선 상대와 `INNER_WINDOW`(2)칸 이내인 상대에 대한 벽만 보고, 경로를 가장 많이 끊는 벽부터 BFS로 재어 봅니다. 후보는 모두 엔진 규칙으로 합법임을 확인하지만(모든 말의 길이 남아야 함), 규칙 엔진의 합법 행동 정의는 바꾸지 않았고, 이득 없는 준비용 벽은 제외됩니다. 그래서 "최적 탐색"이라고 말할 수 없습니다.

난이도 프리셋: 쉬움(깊이 2·0.4초·벽 후보 4/3), 보통(깊이 4·1.2초·8/4), 어려움(깊이 8·3초·10/5). 고급 설정에서 깊이·시간·노드·벽 후보 수·벽 가치·선두 상대 비중·전치표를 조절합니다.

## 실행: Web Worker

Greedy와 Max-N은 워커(`multi.worker`)에서 돌고, Random은 즉시 끝나 메인 스레드에서 처리합니다. `MultiState`와 설정은 구조화 복제로 전달되고, 진행 상황(깊이·노드·시간)이 주기적으로 올라옵니다. 요청마다 id가 있어 취소된 요청의 늦은 응답은 버려집니다. 취소는 워커를 `terminate`하고 다음 요청에서 새로 띄웁니다(동기 탐색이라 중간에 끊을 방법이 없음). 워커 오류가 두 번 연속 나거나 워커를 쓸 수 없으면 **메인 스레드 폴백**으로 바뀌며, UI를 막지 않도록 시간 예산을 80ms로 제한하고 매 결정 앞에 40ms를 비워(페인트·클릭 처리) 실행합니다. 그만큼 약해집니다.

## 세션 (`MultiController`)

- 사람 자리는 입력을 기다리고, AI 자리는 비동기로 결정을 받아 **다시 합법성을 검증**한 뒤 적용·기록합니다(판단 기록은 기보 항목에 붙음).
- 재시작·새 모드·기보 가져오기·무르기·일시정지·`dispose`는 모두 epoch를 올리고 엔진을 취소합니다. 결과는 같은 epoch **이고** 계산을 시작한 바로 그 국면일 때만 적용되므로, 늦게 온 결과가 다른 게임에 반영되거나 같은 국면에 두 번 적용되거나 게임이 끝난 뒤 AI가 두는 일이 없습니다.
- 무르기는 사람의 이전 차례로 돌아갑니다(그 사이 AI 수 포함). AI만 있는 게임은 한 수만 무르고 일시정지합니다.
- AI가 오류를 내거나 불법 수를 내면 가장 가까운 합법 말 이동을 대신 두고 화면에 알립니다(둘 수 있는 수가 없으면 멈춤).
- AI 전용 대국: 진행/일시정지, 한 수(`한 수 ▶|`), 속도(느리게 1.5초 / 보통 0.5초 / 빠르게 0.1초 / 최대).

## 기보

버전 2·3 형식 그대로이고 선택 키 두 개만 추가했습니다(옛 버전은 모르는 키를 무시하므로 버전을 올리지 않음). `participants[].controller`(AI 종류·설정·시드)와 `moves[].ai`(알고리즘·시간·노드·깊이·후보 수 요약; 전체 탐색 기록은 파일이 커져서 저장하지 않음). 가져오기는 모든 수를 엔진으로 검증하고, 읽을 수 없는 AI 설정은 거부합니다. AI 자리가 있는 기보를 불러오면 일시정지 상태로 시작합니다.

## 알려진 한계

- Max-N은 `maxDepth`까지 가지 못하는 경우가 많습니다(어려움도 3초 안에 4~6수 깊이, 벤치마크 참고). 벽 후보 축소 때문에 준비용 벽·희생 벽은 찾지 못합니다.
- 평가식은 거리 기반이라 점프·말 막기 같은 전술을 모릅니다. 난이도 프리셋의 강약은 검증된 순위가 아니며, 몇 판의 승률로 알고리즘의 우열을 말할 수 없습니다.
- 다인전 AI 관전/비교/자동 실험 화면과 Paranoid·MCTS·신경망 AI는 없습니다(3-B 이후).
