2. **[실측] 깊이는 계속 이득**: 깊이 2→3 +160, 3→4 +51, 4→5 +80 Elo(각 200판, 95% CI가 0을 넘음).

4. **[실측] 벽 후보 필터가 강제 승리를 잘라냄**: AB는 깊이 5·300 ms·2 s 모두 같은 5 ply 강제 승리를 놓쳤고, 이기는 수 3개가 전부 `opponent-path` 필터 밖임을 전폭 탐색으로 확인.

6. **[확인] 기존 4 ply 말 이동 오프닝은 고유 국면이 31/100** — 결정적 에이전트의 대국이 중복되어 표본이 과장됨. 새 오프닝으로 해결.
7. **[확인] 현재 학습된 AlphaZero 모델은 TS Alpha-Beta보다 약함**(Stage 7 최종 0승 19패).

**다음에 가장 먼저 구현할 것: TS 엔진 비트보드 BFS** (근거 1·2·3: 노드 비용이 곧 같은 시간의 깊이이고, 깊이가 실력으로 이어짐). 이어서 벽 후보 필터 개선(근거 4), TT·PVS, 종반 해석기, 평가 함수 실험 순(8장).

## 1. 현재 구현과 최적화 현황 [확인]

### 1.1 게임 엔진 (`src/engine`, TypeScript)

| 항목 | 현재 구현 |
|---|---|
| 상태 | 불변 객체 `GameState` — 말 2개(`{row,col}` 객체), 벽 `Uint8Array(64)` 가로/세로 2개, 남은 벽, 차례, 승자, ply |
| 행동 | `{type:'move',to}` / `{type:'wall',orientation,row,col}` 객체. 정수 인덱스 209개(`encoding.ts`)는 TT·학습용 |
| 말 이동 | `pawnMovesAmong`: 직진·점프·대각 처리, `Set`과 배열 할당 |
| 벽 판정 | `wallConflicts`(겹침/교차) → 두 플레이어의 최단 경로를 끊는 벽만 BFS 재검사(경로 절단 지름길, 브루트포스와 동치 테스트) |
| BFS | `distanceToRow`(모듈 스크래치 버퍼, 경로 미복원), `shortestPath`, `distanceMap`(목표 행에서 다중 소스) — 모두 칸 단위 `canStep`→`isBlocked`→`hasHWall` 호출 체인 |
| 상태 변경 | 말 이동은 얕은 복사, 벽 설치는 해당 `Uint8Array` 1개 `slice()` |
| 해시 | Zobrist(32비트 2개 → 52비트 키 + 32비트 검증). **증분 갱신 없음** — 매번 64칸×2 전체 스캔 |
| 비트보드 | **TS 엔진에는 없음.** Python(`training/quoridor_az/bitboard.py`)에는 81비트 정수 비트보드와 벽 배치별 캐시가 있음 |
| 테스트 | 규칙·이동·벽·경로·불변식·최적화 동치·교차 언어 Fixture(433개 상태를 Python이 재현) |

### 1.2 기존 AI

| AI | 탐색 | 평가 | 후보 | 가지치기·TT·캐시 | 시간 제한 |
|---|---|---|---|---|---|
| Random | 없음 | — | 모든 합법 행동 균등 | — | — |
| BFS | 1수 | −d자신 + d상대 − 벽 비용 − 상대 즉시 승리 위협 100 | 모든 합법 행동 | — | — |
| Minimax | 반복 심화 negamax | 거리 경주: d상대 − d자신 + (벽 차이) ± 0.5 템포 | 말 이동 + 상대 최단 경로를 끊는 벽(`opponent-path`) | 없음 | 있음 |
| Alpha-Beta | 반복 심화 negamax α-β, 루트는 이전 반복 순위로 정렬 | 동일(자식 평가는 부모의 거리 맵을 재사용하는 증분 평가) | 동일, 벽 합법성은 탐색 직전까지 지연 | 정적 평가 정렬(남은 깊이 ≥ 3), TT 수, 킬러 2개, `Map` TT(최대 100만, 꽉 차면 전체 삭제), **TT 값은 같은 깊이에서만 재사용**, 결정당 새 TT | 64노드마다 확인, 중단된 반복 폐기 |
| Pure MCTS | UCT(C=1.4) + MCTS-Solver | 휴리스틱 롤아웃 최대 100 ply → tanh(거리 차/3) | Alpha-Beta와 같은 후보 | 트리 상한 20만 노드, 전치 없음 | 시뮬레이션 수 또는 시간 |
| Guided MCTS | PUCT(c=1.5, FPU −0.1) + Solver | 4 ply 휴리스틱 롤아웃 → Minimax 평가의 soft-sign(±0.9) | 같은 후보, 1수 평가 softmax(T=1) 사전 확률 | 동일 | 동일 |

공통: 반복 국면 탐지·무승부 규칙 없음(대국 관리자가 3회 반복 시 "중단"으로 처리), 수 사이 트리/TT 재사용 없음,
PVS·Aspiration·Null-window 없음, 종반 전용 해석기 없음.

### 1.3 AlphaZero 학습 인프라 (`training/`, Python/PyTorch — 이번 단계에서 수정하지 않음)

| 영역 | 상태 |
|---|---|
| 규칙 일치 | TS 엔진이 만든 433개 Fixture(합법 행동 순서·벽 판정 사유·거리·전이·텐서)를 Python이 재현 — 테스트 통과 |
| 상태 인코딩 | `qz-features-v1` 11×9×9(말·벽·막힘·남은 벽·BFS 거리), 차례 플레이어 관점 180° 회전 |
| 행동 공간 | 209 로짓(Stage 7부터 말/벽 유형 2개 + 조건부 209 = 내부 211) |
| 신경망 | ResNet 64×4(기본), Stage 8에서 128×6/128×8 GroupNorm 후보 비교 코드 |
| Neural MCTS | PUCT, Dirichlet, temperature, Virtual Loss, 배치 평가, 트리 재사용(Stage 7) |
| Self-Play | 병렬 lockstep, 중단 대국 `policy-only` 정책, Stage 8.1의 CPU actor + 중앙 GPU 추론 서비스 |
| 학습·저장 | AdamW, EMA(Stage 8), 원자적 체크포인트·SHA256·롤백, Replay 4구간 |
| ONNX | `export_onnx` + onnxruntime 대조 테스트(6A) |
| **실제 학습 결과** | Stage 7(T4, 220 cycle, 1,760게임): 최종 모델이 **Greedy에 1승 13패, TS Alpha-Beta에 0승 19패·3중단**, 교사 holdout Value MSE 2.056→2.323으로 악화(`STAGE8.md`). Stage 8은 cycle 8까지 실행 확인, Stage 8.1 A100 실측은 미실행 |

**결론 [확인]:** 현재 학습된 신경망은 TS Alpha-Beta보다 약하며, 웹에는 AlphaZero 에이전트가 없습니다(`catalog.ts`의 `available: false`).
따라서 현 시점 최강 2인전 AI 후보는 TS 탐색 엔진(Alpha-Beta / Guided MCTS)입니다.

- **[실측]** F7: 가지치기 없는 Minimax와 Alpha-Beta는 같은 깊이에서 같은 강도(동점 처리 차이만), AB가 약 5배 빠름 — 구현 정확성 확인.

자기 손해 벽(자신의 경로를 상대보다 더 늘리는 벽)은 모든 탐색 에이전트에서 0–1회. Pure MCTS는 초반에 벽을 75% 비율로 쓰는 등 벽 낭비가 뚜렷합니다(F6의 "효과 없는 벽" 142개와 일치).

### 5.4 알고리즘별 반복되는 실수 요약

- **Alpha-Beta**: ① `opponent-path` 벽 필터가 수비·준비 벽(현재 상대 최단 경로를 끊지 않는 벽)을 영구히 제외 → 강제 승리 누락 ② 고정 깊이에서는 긴 패배를 구별 못 함 ③ 대국에서 벽을 남긴 채 패배(F5 평균 3.0개 남김).
- **Guided MCTS**: ① 증명된 승리 중 빠른 승리, 증명된 패배 중 긴 저항을 고르지 않음 ② 같은 시간에 AB보다 1수 전술 정확도가 약간 낮음(94% vs 99%).
- **Pure MCTS**: 긴 롤아웃으로 시뮬레이션이 적고(170–1,300/s) 벽을 일찍·효과 없이 사용.
- **BFS**: 1수 휴리스틱 — 즉시 전술은 완벽하나 다수 ply 계산 불가.

## 8. 2단계: Alpha-Beta 강화 개발 계획

측정 근거: 탐색 CPU의 약 70%가 BFS(4장), 깊이 증가가 꾸준히 이득(3.1), 벽 필터가 강제 승리를 잘라냄(5.2), 같은 고정 예산에서 Guided MCTS에 −185 Elo(3.1).

## 9. 실행 방법·검증·미완료 항목

### 9.1 실행 명령 (Windows PowerShell, 저장소 루트)

Git Bash에서 파일 하나만 지정한 `vitest run`은 경로 대소문자 문제로 실패하므로 PowerShell을 사용합니다.

```powershell
# 대국 스위트 (재실행하면 이어서 진행; 고정 예산은 병렬 샤드 권장)
powershell -ExecutionPolicy Bypass -File bench/run-shards.ps1 -Suite stage1-fixed -Shards 6
powershell -ExecutionPolicy Bypass -File bench/run-shards.ps1 -Suite stage1-time  -Shards 4   # 다른 부하 없이
# 일부만 / 단계 실행 / 보고서만
$env:SUITE='stage1-time'; $env:MATCHUPS='T2000-ab-vs-guided'; $env:LIMIT='10'; npx vitest run --config vitest.bench.config.ts bench/stage1.bench.test.ts
$env:SUITE='stage1-fixed'; $env:REPORT='only'; npx vitest run --config vitest.bench.config.ts bench/stage1.bench.test.ts
# 병목 프로파일 (유휴 상태에서)
npx vitest run --config vitest.bench.config.ts bench/profile.bench.test.ts
# 전술 테스트: 국면 추출(기존 파일이 있으면 거부) / 실행
$env:TACTICS='mine'; npx vitest run --config vitest.bench.config.ts bench/tactics.bench.test.ts
$env:TACTICS='run'; $env:AGENTS='bfs,ab4,ab-2s,guided3000'; npx vitest run --config vitest.bench.config.ts bench/tactics.bench.test.ts
# 고정 예산 재현성 감사
$env:SUITE='stage1-fixed'; $env:SAMPLE='3'; npx vitest run --config vitest.bench.config.ts bench/reproduce.bench.test.ts
```

주의: 전술 스위치에 `MODE`를 쓰면 안 됩니다 — Vite/Vitest가 `process.env.MODE`를 `test`로 덮어씁니다(초기 구현의 실제 오류). `TACTICS`를 사용합니다.
