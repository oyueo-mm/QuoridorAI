## 3. 시간 관리 (3-C-1)

**다음 깊이의 예상 비용**:
- 깊이가 1 늘 때 노드 배율(EBF)은 중앙값 1.8입니다(홀수 깊이로 3.0, 짝수로 1.85, 3-B 측정).
- 마지막으로 끝난 반복이 전체 완료 시간의 약 55%를 차지합니다.
- 그래서 다음 반복은 남은 시간 안에 거의 끝나지 않습니다.

**중단 판단·시간 배분 검토**:
- 수당 시간이 고정(300 ms)이라 일찍 멈춰도 아낀 시간을 다음 수로 넘길 수 없습니다. 끝날 가망이 없는 반복을 시작하지 않는 규칙은 **강도를 올리지 못하고** 응답만 빨라집니다.
- 대국 전체 시계(시간 은행)가 있다면 수 사이 배분이 의미가 있지만, 현재 대전 규칙에는 없습니다. 그래서 구현하지 않았습니다.

**마지막 완료 결과 보존 + 중단 반복의 안전한 활용 (`partialIteration`)**:
- 마지막으로 끝난 반복의 결과(후보·트리·점수)는 항상 그대로 보존합니다.
- 중단된 반복에서는 이전 최선 수를 가장 먼저 탐색합니다. 이 수는 전체 창으로 탐색되므로 끝나면 그 깊이의 **정확한 값**이 나옵니다.
- 다른 수가 그 깊이에서 **끝까지** 탐색되고 그 정확한 값이 이전 최선 수의 값보다 **높을 때만** 그 수를 둡니다. 루트에서 앞선 수들을 모두 이긴 수의 값은 정확합니다.
- 동점, 상한만 증명된 수, 끝나지 않은 수는 절대 쓰지 않습니다.
- 검증 [확인]: 결정적 시계로 반복을 여러 지점에서 끊어서 확인했습니다.
  - 수를 바꾼 경우: 바꾼 수의 값과 이전 최선 수의 값 모두 독립적인 정확 탐색과 같았습니다.
  - 바꾸지 않은 경우: 수와 점수가 기존 탐색과 같았습니다.
- 측정 [실측]: 오프닝 수의 **10%** 에서 수가 바뀌었고 중반·종반은 0%였습니다. 버려지는 시간 자체는 그대로이고, 그 안의 정보만 일부 회수합니다.
- 분석 패널 설명에 "깊이 d+1 탐색 중 끝난 수가 더 좋아 선택" 문구를 추가했습니다.

## 4. 전치표 (3-C-2)

### 4.1 분석과 결정

| 항목 | 분석 | 결정 |
|---|---|---|
| 증분 Zobrist | `hashState`는 CPU의 **0.4%** | **구현하지 않음** — 이득 ≤ 0.4% |
| TypedArray 표 | 키 하위 32비트 + 검사값 32비트로 항목을 완전히 식별(52비트 키의 상위 20비트는 검사값의 일부). 2칸 버킷: 0번 칸은 더 깊은 항목/현재 탐색 우선, 1번 칸은 항상 새 항목. 이전 탐색(세대) 항목부터 교체. 2^19칸 ≈ **10.5 MB 고정** (Map은 100만 개에서 전체 삭제, 최대 약 100 MB) | 구현(`ttKind: 'typed'`). 같은 깊이 5에서 노드 수까지 기존과 **동일** |
| 탐색마다 초기화하지 않기 | 에이전트마다 표와 평가기를 유지. **서명**(평가 가중치·후보 필터·알고리즘·**루트 쪽**)이 바뀌면 비움. E5/E6는 가중치가 비대칭(자기 거리 1.001, 상대 거리 1)이라 루트 쪽이 다르면 저장값이 틀립니다 | 구현(`ttPersist`). 대국마다 새 에이전트(아레나), 웹 워커는 에이전트당 하나 |
| EXACT / LOWER / UPPER | 기존 규칙 유지: 같은 남은 깊이에서만 컷오프. EXACT는 그대로, LOWER는 α, UPPER는 β를 좁힘. 실패-저(fail-low) 노드는 이전 최선 수를 유지. 결정적 점수는 노드 기준으로 저장 | 변경 없음 |
| 더 깊은 항목으로 컷오프 | 결과가 달라지는 변경. 측정: 수 사이 유지와 함께 **+0.02 ply** | **패키지에서 제외**(옵션 `ttDeeper`만 남김) |
| 분석 트리 노드(1–2 ply)의 TT 컷오프 제외 | 허용해도 노드 −0.0% | 변경 없음 |

| 변경 | 고정 깊이 결과 | 시간 제한 결과 |

## 5. PVS (3-C-2)

- 구현: 첫 수 이후는 영창(α, α + ε)으로 탐색하고, α < v < β이면 전체 창으로 재탐색합니다.
  - 점수가 실수 가중치 합이라 ε = 10⁻⁶을 씁니다. 창 안의 실패-고(fail-high)는 항상 재탐색하므로 ε 크기와 무관하게 정확합니다.
  - 루트도 같은 방식입니다.
  - 자식이 리프인 노드(남은 깊이 1)는 영창 이득이 없어 적용하지 않습니다.
  - TT는 영창 탐색의 경계를 그대로 저장합니다(기존 EXACT/LOWER/UPPER 규칙).
- 정확성 [확인] (`src/ai/__tests__/stage3cSearch.test.ts`):
  - 무작위 14국면 × 깊이 1–4 × (v1, E6) × (typed, pvs, typed+pvs)에서 루트 점수가 **비트 단위로 같았습니다**.
  - 최선 수가 다르면 두 수의 정확한 값이 같은지(동점) 따로 확인했습니다.
  - 루트 후보의 상한이 minimax 정확값 이상인지(경계의 건전성)도 확인했습니다.
  - 실제 대국 90국면(깊이 5)에서는 점수 90/90, **최선 수 90/90이 같았습니다**(동점 차이 0건).
- 노드·시간 [실측, 깊이 5]:

| 단계 | 노드 (기준 대비) | 시간 |
|---|---:|---:|
| 오프닝 | **0.951** | 7,128 → 6,634 ms |
| 중반 | 0.976 | 4,516 → 4,431 ms |
| 종반 | 0.996 | 1,218 → 1,214 ms |

- 300 ms 완료 깊이 변화는 +0.04 / −0.04 / 0으로 잡음 범위입니다.
- PVS의 이득은 정렬이 좋고 트리가 클수록 큽니다. 지금은 남은 깊이 3 미만 노드의 정렬이 약해(정적 정렬 없음, TT·킬러만) 재탐색 비용이 이득을 상쇄합니다.

- **312번의 빈틈**: 2차 시도가 대국 시간 제한(절전)으로 중단됐지만 수 하나하나는 예산을 넘지 않아 의심 대국으로 분류되지 않았습니다. 그래서 재대국되지 않았습니다. 그 쌍은 '중단 쌍'으로 SPRT에서 빠졌기 때문에 결과는 같습니다. 이후 규칙을 고쳤습니다(9장).
- **전원 상태**:
  - 20:09–00:33(KST) 4시간 23분 동안 4개 프로세스가 모두 멈췄습니다(절전).
  - 깨어난 뒤 35분 동안의 대국은 초당 노드 수가 **2.5배 낮아**(11.6k vs 29.3k) **배터리 전원**으로 판정됩니다.
  - 파이프라인도 01:08에 배터리를 감지했습니다.

| 부분 | 쌍 | 쌍 점수 (95% CI) | 정확한 GSPRT |
|---|---:|---|---|
| AC (절전 전) | 137 | 0.547 (0.496–0.599) | LLR +1.60, Elo +33 (−3 … +70) — **미결** |
| 배터리 (깬 뒤) | 220 | 0.541 (0.497–0.585) | LLR +1.62, Elo +28 (−2 … +60) — 미결 |
| 전체 | 357 | 0.542 | **H1 수용** |

**해석**:
- 같은 대국의 두 쪽은 같은 조건이라 비교는 공정합니다. 효과도 두 부분에서 같아 전원에 따른 차이의 징후는 없습니다.
- 그러나 배터리 300 ms는 AC 기준 약 120 ms에 해당하는 다른 시간 조건입니다.
- 3-B에서 정한 "동일 시간 실험은 AC 전원" 규칙을 지키지 못했으므로, 이 결과만으로 기본값을 바꾸지 않았습니다. 확인 SPRT를 AC 전원과 새 오프닝으로 진행했습니다.

## 7. 기여도 분석

| 구성 요소 | 고정 깊이 결과 | 노드 (깊이 5) | 300 ms 효과 | 기대 강도 [추정] |

| **수 사이 유지** | 점수 동일 | — | **+0.16 ply**, 수당 노드 +12% | 1단계 기준 +51–160 Elo/ply → **약 +8–26 Elo** |

- 구성 요소별 Elo는 각각 SPRT가 필요합니다(효과가 작아 각 1–3시간).

## 8. 채택

| 구성 요소 | 상태 | 근거 |
|---|---|---|
| **C1 패키지** (typed TT + PVS + 수 사이 유지 + 중단 반복) | **채택 — 기본 탐색** | 독립 오프닝 SPRT 2회 승격(+29 혼합 전원, +58 AC), 고정 깊이 점수 동일, 전술 회귀 없음 |
| 더 깊은 TT 항목 컷오프 | 불채택(옵션 `ttDeeper`) | +0.02 ply, 결과가 달라지는 변경 |
| 증분 Zobrist | 구현 안 함 | CPU 0.4% |

- 기존 탐색은 `ORIGINAL_SEARCH`(`src/ai/minimaxAgent.ts`)로 언제든 다시 켤 수 있습니다. 테스트와 프로파일 도구는 이것을 기준선으로 씁니다.
- 앱의 Alpha-Beta(웹 워커)도 같은 기본값을 씁니다. 워커는 에이전트 하나만 맡으므로 표가 같은 에이전트의 수 사이에서만 유지됩니다. 같은 쪽·같은 설정이 아니면 비웁니다.
- 주의: 탐색 옵션을 명시하지 않은 기존 벤치마크 정의(예: `stage3c`의 "baseline search")는 이제 C1로 실행됩니다. 완료된 결과에는 영향이 없지만, 다시 돌리면 이전 기록과 섞으면 안 됩니다. 이후 실험은 `ORIGINAL_SEARCH` 같은 옵션을 명시합니다.

## 10. 다음 단계: Aspiration Window, History Heuristic, LMR 적용 순서 제안

측정 근거:
- 내부 노드당 컷오프 0.46–0.63, TT 적중 37–67%, PVS 이득이 작음 → **얕은 노드의 수 정렬이 약하다**는 신호입니다. 남은 깊이 3 미만에는 TT 수·킬러만 있습니다.
- 시간의 약 65%가 평가와 경로 BFS입니다.

| 순서 | 항목 | 이유 | 결과 동일성 | 검증 |
|---|---|---|---|---|
| 1 | **History heuristic** (남은 깊이 < 3 노드 정렬) | 정렬만 바꾸므로 고정 깊이 점수가 같고 비용이 거의 없음. PVS·LMR 모두 정렬 품질에 의존해 둘의 효과를 키우는 **기반** | 점수 동일(동점 수만 다를 수 있음) | 동일성 테스트 → 깊이 5 노드 → 300 ms 완료 깊이 |
| 2 | **Aspiration Window** | PVS가 들어와 재탐색 체계가 있음. 기대 이득은 작음(5–10% [추정]). 홀짝 깊이 점수 진동이 커서 기준은 d−2 점수, 창 폭은 측정으로 결정 | 재탐색 포함 시 점수 동일 | 동일성 테스트, 재탐색 비율·노드 |
| 3 | **LMR** | 가장 큰 잠재 이득(+0.5–1 ply [추정])이지만 **결과가 바뀌고 전술 위험이 큼**(벽 한 수가 전술). 좋은 정렬(1번) 위에서만 의미가 있음. 2단계의 보호 벽(같은 깊이 +42, 비용 5×)을 "정렬 맨 뒤 + 감소"로 싸게 넣는 실험과 묶음 | 다름 | 전술 세트(5 ply 승리·종반) → 비용 관문 → 예비 → SPRT → 확인 SPRT (모두 AC) |

1–2번은 결과가 같은 최적화라 묶어서 SPRT 한 번(+ 독립 확인)으로 확인할 수 있습니다. 새 기준선은 C1입니다.

**별도 권고**: 시간의 약 40%를 쓰는 E6 취약성 평가의 형제 노드 간 증분 계산은 탐색 기법보다 큰 속도 지렛대일 수 있습니다. 결과가 같은 최적화로 3-C-3 후보에 넣는 것을 권합니다.
