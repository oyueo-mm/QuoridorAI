# Stage 3-D 최종 감사 — E6 계산 최적화

작성: 2026-11-15, KST. 연구 브랜치 `stage1-benchmark`. 완료된 벤치마크를 재실행하지 않고 원시 기록·설정·로그·소스를 감사했다.

> **후속 마무리: fast 기본값 채택.** 새 seed 98004의 단 한 차례 독립 확인은 224유효 쌍에서 H1 수용, Elo +32.67 [95% CI +6.54,+59.18], LLR 2.95974로 종료됐다. 오프닝 독립성·AC·무효 처리 최종 감사 및 전체 검증을 통과했다. 최신 판정·통계·롤백은 [독립 확인 최종 보고서](stage3d-independent-report.md)에 있다. 아래 본문은 커밋 `9c2d530` 당시의 초기 감사와 보류 근거를 보존한 역사 기록이며, 원본 C의 중복 결함을 없던 것으로 바꾸지 않는다.

## 1. 초기 감사 판정(독립 확인 보완 전)

**fast 기본값 채택 보류. 기본 평가 커널은 `reference`를 유지한다.**

속도와 정확성은 확인됐다. 원본 최초 SPRT와 확인 SPRT도 각각 H1을 수용했다. 그러나 확인 실험의 원래 판정 구간에는 파일럿과 겹치는 오프닝 1쌍, 최초 SPRT와 겹치는 오프닝 1쌍이 있었다. 두 쌍을 결과와 무관한 중복 기준으로 제외하고 **원래 중단 시점까지만** 다시 계산하면 LLR 2.76548로 승격 경계 2.94444에 도달하지 않는다.

따라서 사전에 요구한 **독립 오프닝 확인 SPRT 통과**를 충족했다고 확정할 수 없다. 이는 fast가 열등하거나 reference와 동등하다는 판정이 아니다. 개선 증거는 있으나 정해진 채택 절차의 독립 확인이 미완료다. 이번 세션에서는 추가 대국을 실행하지 않았고, 불리한 기록을 삭제하거나 다른 설정의 결과로 대체하지 않았다.

`evalKernel: 'fast'` 옵션과 `reference` 구현을 모두 보존한다. 다음 단계 알고리즘은 구현하지 않았다. main 병합과 배포도 하지 않았다.

## 3. 조건과 원본 결과

양측 모두 C1 탐색(typed TT, PVS, 수 사이 TT 유지, 검증된 중단 반복), masked BFS, opponent-path 후보, E6를 사용한다. 변경 변수는 명시적인 `evalKernel`이다. 시간은 양측 **수당 300ms**, 동일 오프닝을 선후공 교환하여 2판씩 평가했다.

| 실험 | seed | config hash | 목적 |
|---|---:|---|---|
| P-D-300 | 98001 | `5270e0ed4c8847fc` | 파일럿 40쌍 |

P-D-300은 37유효 쌍, 쌍 점수 0.54054 [0.44464, 0.63644], 무효 3/40쌍이었다. 파일럿 관문은 미완료, CI 상한 <0.5, 무효 >10%인 경우 중단하는 규칙이다. 이 파일럿은 관문을 통과했지만, 자체적으로 유의한 개선을 입증한 것은 아니다.

## 4. 오프닝 독립성 감사

문자열뿐 아니라 시작 국면을 재생하고 `mirrorInvariantKey`로 좌우 반사까지 정규화했다. 각 실험 내부의 시작 국면은 유일하다. 기존 3-C까지의 제외 ledger는 4,641개이며 P/T/C 실제 국면과의 교집합은 모두 0이다.

| 비교 | 실제 사용 국면의 교집합 | 전체 생성 일정의 교집합 |
|---|---:|---:|
| P ↔ T | 0 | 0 |
| P ↔ C | **1** | 1 |
| T ↔ C | **1** | 7 |

서로 다른 seed만 사용하고 동일한 **3-C까지의 ledger**를 재사용했기 때문에, P/T의 새로운 국면은 C의 제외 목록에 없었다.

| 키 | 선행 실험 / pair | C pair | C 쌍 점수 |
|---|---|---:|---:|
| `1464311824658509:1396476306` | P / 18 | 436 | 1 |
| `2459531624619449:2345594769` | T / 17 | 492 | 0.5 |

둘 다 C의 원래 판정 구간에 들어간다. 실제 사용한 선행 국면을 제외하면 **495유효 쌍 / 990판**, LL 74 / 분할 314 / WW 107, 점수 0.533333 [0.506834,0.559833], Elo +23.20 [+4.75,+41.78], **LLR 2.765481 → continue**다. 이는 완료된 새 확인 실험의 판정이 아니라, 기존 중단 구간에서의 사후 민감도 분석이다. 더 돌리지 않았으므로 최대 표본에 도달한 `inconclusive`와도 구분한다.

감사에는 P/T의 **미실행 부분까지 포함한 전체 일정**을 제외하는 다른 민감도 분석도 남겼다. 이 필터에서는 H1 경계를 통과하지만 원래 실험에 사전 등록한 제외 규칙이 아니다. 유리한 사후 필터를 선택해 독립 확인 통과로 바꾸지 않는다. 원본 판정·모든 필터·중복 키를 audit.json에 공개했다.

동일한 90국면에서 노드 수는 위 속도 실험과 같다. 취약성 캐시 hit는 46.8/49.9/56.0%, miss 수는 138,009/67,375/17,368로 양측 동일하다. miss당 fast 후보 질의는 10.01/10.21/8.64개로 reference의 13.19/15.23/11.78개보다 적다. cheap-detour의 증명 가능한 상한과 layered BFS가 실제 질의 비용을 줄인다.

프로파일러의 `other-js`에는 분류 규칙에 없는 `engine/rowMasks.ts` 함수가 들어간다. 그 비율을 순수한 미확인 오버헤드로 해석하지 않는다. fast 실행에서 reference 전용 counters가 0인 것도 해당 구현을 호출하지 않았다는 뜻이며 계산량 전체가 0이라는 뜻은 아니다. GC self는 reference 126/66/14ms, fast 117/63/17ms로, 상대 비율 상승만으로 메모리 회귀를 결론내리지 않는다.

**RSS·heap peak·할당 바이트의 실측 비교는 기존 산출물에 없다.** 새 메모리 벤치마크를 실행하지 않았으므로 메모리가 줄었다고 확정하지 않는다. 아래는 소스의 TypedArray payload 정적 계산이다.

| 항목 | 확인 가능한 비용 |
|---|---|
| C1 TT | 양측 동일: 2^19 × 21 = 11,010,048 bytes = 10.5MiB/에이전트 |
| 3-D 추가 모듈 scratch | 8,946 bytes: layered 2×82×11×4 + 범위 2×82 + 7×11×4 + 경로 81×2 + cross 2×9×4 + deferred 256×4 |
| fast의 goal-row 공유 맵 | 벽 배열 객체 조합당 최대 2×81×2 = 324 bytes, 지연 할당 |
| 취약성 캐시 값 배열 | 양측 동일 162 bytes/layout, 최대 100,000 layouts/evaluator; JS Map/객체/키 비용 별도 |

scratch는 reference 실행 시에도 같은 모듈이 로드되어 할당된다. 공유 맵은 별도 WeakMap 캐시이므로 취약성 캐시의 100,000개 제한을 그대로 적용한 전체 메모리 상한을 만들 수 없다. 원래 문자열 키가 숫자 hash + 충돌 chain으로 바뀐 객체 비용도 실측이 필요하다.

장시간 절전을 나타내는 로그 공백이나 120초 게임 제한 중단은 발견되지 않았다. 이것은 로그에 드러난 범위의 결론이며 OS 절전 이벤트를 별도 수집한 것은 아니다.

C의 game index 770: 1차는 b-win, 최대 한 수 1,011.54ms > 900ms(3×예산), `overBudgetMoves=1`. 기존 최대 3회 시도 규칙에 따라 재대국했고 2차 a-win, 시간 초과 표시 0이 최종 기록으로 사용됐다. 원래 패배 행은 그대로 보존했다. 모든 raw 행의 실제 decision ms로 overBudgetMoves를 재검산했고, 최종 집계에는 의심 시도가 0건이다. 744ms 같은 3배 미만 지연은 기존 규칙상 유효하며, 이번 결과를 보고 새 제외 기준을 적용하지 않았다.

반복 중단은 재대국 대상이 아니다. 한쪽 판이 반복 중단인 쌍 전체를 SPRT에서 제외한다. C의 반복 중단 25판과 중단 쌍 23개가 다른 것은 같은 쌍의 양쪽 중단 때문이다.

## 8. c0492f1과 3-D reference의 차이

**같은 평가 정의와 예전 취약성 BFS이지만, 과거 커밋 전체를 그대로 실행한 대조군은 아니다.**

| 항목 | 확인 |
|---|---|
| E6 가중치 | self 1.001 / opponent 1 / wall 1.503 / tempo 0.482 / vulnerabilityThreat 0.5 유지 |
| `vulnerabilityReference` 본문 | c0492f1의 `vulnerability`와 공백·이름 외 동일 |
| reference prepare/query BFS | c0492f1과 diagnostic counter 증가문 외 본문 동일 |
| minimaxAgent / candidates / transposition | c0492f1과 파일 동일 |
| runSearch | 평가 커널을 동기 범위에서 설정하고 finally 복구하는 wrapper 추가 |
| 공통 변경 | wall-driven 마스크 생성, 마지막 마스크 memo, 취약성 캐시 string→정확한 충돌 검증 hash-chain, 진단 counters |
| fast에서만 사용 | layered 질의, 객체 없는 path/candidate, cheap-detour deferral, childEvaluator의 goal-row 공유 맵 |

E6의 취약성은 자기 최단 경로를 자르는 충돌 없는 단일 벽의 최대 유한 거리 증가다. 그 벽이 **다른 플레이어의 길까지 보장하는지 검사하지 않는 기존 휴리스틱 정의**도 유지했다. 계산을 빠르게 한다고 이 정의를 바꾸지 않았다.

따라서 보고된 +66/+24 Elo는 **3-D 공통 코드 위에서 reference→fast로 바꾼 효과**다. 공통 최적화를 포함한 c0492f1 대비 전체 3-D 효과를 직접 측정한 Elo나 배율은 없다. 단순 합산이나 역산으로 만들지 않는다.

## 10. 다음 조치
