# 3-D 이후 탐색 최적화 계획 — 구현 미착수

2026-11-15. 이번 세션에서는 아래 기법을 구현하거나 새 강도 실험을 시작하지 않았다.

## 1. 먼저 고정할 기준

3-D 감사에서 독립 확인 오프닝 중복이 발견되어 fast 승격을 보류했다([최종 보고서](stage3d-eval-report.md)). 후속 후보의 기준선은 현재 **E6 + C1 + reference**다. fast를 별도로 승격하면 그 커밋·설정과 새 실험 ID를 기준으로 삼고, reference 기반 결과와 섞지 않는다. 모든 옵션을 config에 명시하며 C1과 커널을 default spread에만 의존하지 않는다.

우선순위는 **독립성 절차 정리 → History → Aspiration → LMR**를 권한다. History/Aspiration은 완전 재탐색을 포함한 고정 깊이 점수 보존을 목표로 하고, LMR은 선택적 탐색으로 결과가 바뀌는 후보로 분리한다. 각각 단독 효과를 먼저 확인하고 조합을 별도 실험한다.

아래 수치 관문은 **앞으로 실행 전에 확정할 제안**이다. 이번 결과에서 이미 입증한 효과가 아니며 기대 Elo를 배정하지 않는다.

## 2. History Heuristic

내부 노드의 성공적인 cutoff 행동을 누적해 정렬에 쓰는 원리는 [Schaeffer의 원 논문](https://journals.sagepub.com/doi/10.3233/ICG-1983-6305)에 제시돼 있다. 해당 논문의 체스 속도 개선 수치를 쿼리도에 이식하지 않는다.

### 구현 제안

현재 `minimax.ts`의 `expand()`는 남은 깊이 3 미만에서 즉시 승리·TT·killer만 정렬한다. 여기에 **깊이 1–2의 저렴한 보조 순서**부터 넣는다. `storeKiller()`를 호출하는 beta cutoff에서 실제로 합법성이 확인된 행동만 보상한다.

- 벽: side × 128 wall slots. 말: side × 출발 81 × 도착 81. 단순 목적지 81만으로 시작할 수도 있으나, 같은 도착 칸의 다른 점프/출발 맥락이 섞이는 대안으로 별도 비교한다.
- Int16 보관 시 말+벽 합계 `(2×81×81 + 2×128)×2 = 26,756 bytes`/에이전트. 계산·갱신은 number로 수행하고 포화시켜 overflow를 막는다.
- 초기 규칙은 `depth²` 보상, 깊이별 상한 및 aging. gravity식 보정이나 실패 후보 penalty는 같은 실험에 한꺼번에 추가하지 않는다.
- 정렬 우선순위는 즉시 승리 > TT > killer > history > 원래 순서. 안정 정렬로 동점 처리한다. 깊은 노드의 static ordering은 우선 유지한다.
- TT/평가 캐시와 마찬가지로 에이전트별 소유권을 두고 새 경기·root 관점/설정 변경 때 초기화한다. 첫 버전은 수 사이 유지 여부를 하나로 고정하고 보고한다. 다른 AI나 워커와 공유하지 않는다.

### 효과·위험·검증

측정된 PVS의 작은 이득과 얕은 노드 정렬 부재에 대응하는 후보다. cutoff가 앞당겨지면 평가/BFS 호출을 줄일 수 있으나, wall slot의 맥락 차이·양쪽 root 관점·초기 history 누적이 편향을 만들 수 있다. 정렬 비용이 절감보다 클 수도 있다.

검증은 무작위/실전·벽 밀집·점프·종반 국면, 양쪽 root, 깊이 1–5에서 full-window reference 점수 동일성부터 한다. 동점 수가 달라지면 두 후보의 정확 점수를 검증한다. 노드 동일성은 요구하지 않는다. cutoff rank, 정렬 평가 횟수, PVS 재탐색, 노드/경과 시간, 300ms의 완료 깊이 및 timeout tail을 기록한다.

실행 전 제안 관문: 고정 깊이 점수 불일치 0, 정확 전술 신규 실패 0, 단계별 경과 시간 기하평균 ≤0.95, 개별 단계 >1.05 회귀가 있으면 원인을 먼저 확인. 이 수치는 승격 근거가 아닌 비싼 강도 실험을 시작할 비용 관문이다. 통과 후 40쌍 파일럿 → 300ms SPRT → 완전히 분리된 확인을 한다.

## 3. Aspiration Window

루트 창을 이전 점수 주변으로 좁히고 실패 때 넓혀 재탐색하는 구현 예는 [Stockfish의 공식 search.cpp](https://github.com/official-stockfish/Stockfish/blob/master/src/search.cpp)에 있다. 같은 파일의 계수나 체스 전용 조건을 복사하지 않고 현재 쿼리도 점수 단위에 맞춰 설계한다.

### 구현 제안

현재 `searchRoot(depth)`의 루트는 alpha=-INF, beta=INF인 형태다. `searchRoot(depth, alpha, beta)`로 명시하고 루트 결과에 EXACT/UPPER/LOWER를 반환하게 할 필요가 있다. fail-low/high 경계값을 정확 점수처럼 `iterations`, `rootCandidates`, 기보 분석에 노출하면 안 된다.

- depth 1은 full window. 이후 완료 반복 d−1을 기본 중심으로 사용한다. E6의 root 관점·깊이 홀짝 진동은 실제 분포를 측정해 d−2 중심과 비교하며 d−2가 무조건 좋다고 가정하지 않는다.
- 탐색 전 순서가 고정된 개발용 국면으로 폭 후보(예: E6 단위 0.5/1/2/4 또는 점수 변화 분위수 기반)를 좁힌다. 강도 확인 오프닝은 폭 선택에 쓰지 않는다.
- fail 방향의 창을 단조롭게 넓히고 반복 실패 시 full window로 복귀한다. 처음부터 같은 목표 깊이를 유지한다. 재탐색 중 depth를 낮추면 점수 보존 후보가 아니게 된다.
- 재탐색도 **원래 한 수의 deadline** 안에서 수행한다. 재시도마다 300ms를 새로 지급하지 않는다. 창 안으로 수렴한 반복만 completedDepth를 올린다.
- C1의 partialIteration이 현재 가정하는 루트 정확성은 좁은 창에서 깨질 수 있다. 미수렴 aspiration 반복에서는 partial 교체를 막는 보수적 버전을 우선 검증하고, 그 상호작용을 별도 ablation으로 보고한다.
- TT에는 실제 검색 깊이와 올바른 bound만 저장한다. 실패한 창의 최고 값으로 PV나 EXACT를 확정하지 않는다. float 비교 및 기존 PVS epsilon도 경계 테스트한다.

### 효과·위험·검증

기대 경로는 창 축소에 따른 cutoff 증가다. 점수 진동·승패 증명 값·벽 전술로 fail 반복이 많으면 총 시간이 늘고 마지막 완료 깊이가 낮아질 수 있다. 현재 엔진에서 이득의 크기는 미측정이다.

깊이 1–5 고정 점수 동일성, root bound, fail-high/low 연속 전환, 강제 full-window fallback, 재탐색 중 취소·시간 초과, TT warm/cold, 승패 거리와 PV 합법성을 검사한다. 첫 시도 성공률, 평균/최대 재탐색 횟수, 재탐색 노드 비율, 홀짝 score delta, 300ms 완료 깊이와 latency tail을 기록한다.

실행 전 제안 관문: correctness와 전술 회귀 0, 전체 경과 시간 비율 ≤0.95, 시간 초과/재탐색 tail 악화 시 보류. History가 켜진 기준에 더하는 효과와 둘을 합친 최종 패키지 효과를 구분한다. 비용 관문 후 동일 시간·독립 오프닝 SPRT와 확인이 필요하다.

## 4. Late Move Reduction (LMR)

좋게 정렬된 뒤쪽 행동을 얕게 선별하고 유망하면 원래 깊이로 재검증하는 선택적 탐색 후보다. 공식 구현 참고는 위 Stockfish 소스이며, 아래 적용 조건은 **이 저장소를 위한 설계 제안**이다.

### 구현 제안

기존 `negamax`의 PVS 자식 탐색 전후가 적용 지점이다. 첫 실험은 남은 깊이 ≥4, non-PV, 최소 앞의 4개 **합법 행동을 실제 탐색한 뒤**, 1 ply 감소만 허용한다. 첫/TT/killer 수, history 상위 수, 즉시 승리·방어, 승패 증명 구간, goal 인접·강제 점프, 전술 위험 벽은 보호한다. pseudo 후보 index가 아니라 합법 탐색 순번을 센다.

쿼리도에서는 조용해 보이는 벽 한 수가 경주를 결정한다. 첫 버전은 보호 조건을 만족하는 제한된 말 이동부터 적용하는 대안과 벽까지 확장하는 대안을 분리한다. 보호 판정을 위해 매 후보마다 추가 BFS를 수행하면 비용을 상쇄할 수 있으므로 기존 경로·전술 메타데이터 재사용 여부를 측정한다.

감소 탐색이 alpha를 넘으면 원래 깊이에서 재탐색하고, 필요한 경우 PVS의 full-window 재탐색까지 진행한다. 다만 감소 탐색이 잘못 fail-low한 유망 수는 재탐색되지 않을 수 있다. 따라서 이 절차만으로 완전 탐색과 동일성을 보장하지 않는다.

TT에는 실제 검색 깊이·bound를 정직하게 저장하고 감소값을 원래 깊이의 EXACT처럼 쓰지 않는다. 기존 root partialIteration의 증명 조건도 검토한다. LMR의 "깊이 8"은 완전 깊이 8과 정보량이 같지 않으므로, 표면적 완료 깊이만으로 승격하지 않는다.

### 효과·위험·검증

가장 큰 노드 절감 잠재력이 있지만 방어 벽, 우회 길, 급한 경주·zugzwang 유사 상황에서 전술을 놓칠 위험이 가장 크다. 목표 Elo나 +0.5~1 ply 같은 수치를 사실로 제시하지 않는다. 현재 opponent-path filter 밖에 없는 수는 LMR로도 복구되지 않는다. 후보 확장과 LMR을 함께 바꾸면 별도 후보로 검정해야 한다.

전술 exact 141개 전체와 별도 blind 추가 세트(방어 벽, win-in-5, 점프·복도, 벽 소진 종반)를 사용한다. 기존 정답을 외운 보호 규칙은 만들지 않는다. 원래 깊이 full search와 달라진 모든 root 선택은 정확성 실패로 자동 단정하지 않고 개별 진단하되, 증명된 전술 신규 실패는 관문에서 중단한다. TT 오염·취소·재탐색·정규 2인 외 경로 비활성화도 확인한다.

감소 횟수/평균 감소량, 재탐색 비율, 검증된 root 변경, nodes/time, 단위 시간 전술 정답, 100/300/1000ms에서의 안정성을 먼저 본다. 주된 강도 승격은 사전에 정한 300ms 기준의 두 독립 SPRT이며, 추가 시간 조건은 별도 ID와 예산으로 사전 결정한다.

## 5. 실험 비용과 순서

3-D 실측 비용은 파일럿 80판 약 6.6분, T 199판 약 15분, C 1,063시도 약 77.8분이다. 같은 기기·4샤드·AC의 관측 처리율로 단순 계획하면 40쌍 파일럿은 약 6–8분, SPRT 한 번은 최대 일정 1,200판에서 약 90–100분, 독립 확인까지 합치면 강도 실험만 후보당 약 3시간대의 상한 예산이 필요하다. 절전/재대국·기보 길이·새 알고리즘 변화는 더 늘릴 수 있다. 조기 종료하면 짧아진다. 이는 **계획 추정**이며 실행 시간을 보장하지 않는다.

| 단계 | 준비/계측 계획 | 실행 전 정할 관문 |
|---|---|---|
| 3-D 독립 확인 보완 | 새 ID·seed·누적 ledger·결과 디렉터리, 기존 결과 유지 | 사전 생성 일정과 이전 일정의 mirror 교집합 0, AC, H0/H1 그대로 |
| History 단독 | 구현·단위/고정 깊이·전술 확인 후 프로파일(개발 작업 약 0.5–1일 예상) | 점수 동일, 전술 회귀 0, 비용 관문 → P/T/C |
| Aspiration 추가 | root bound·timeout/partial 계약 검증(약 1–2일 예상) | 재탐색 포함 점수 동일, tail 검증 → P/T/C |
| LMR | 보호/TT 의미 설계와 별도 전술 진단(약 2–4일 예상) | 선택적 탐색 위험 통과, 새 blind 세트 → P/T/C |

개발 일수도 작업 분할을 위한 추정이다. 고정 깊이/프로파일은 각 단계의 실행 전에 소수 국면으로 시간 상한을 정하고, 비용이 불리하면 대국 전에 중단한다. 여러 폭·감소 계수를 같은 확인 세트에서 반복 선택하지 않는다. 모든 실패와 미결을 보존하고 후보 수에 따른 다중 검정 위험을 보고한다. 첫 후보는 하나로 고정하고, 선택 단계 데이터와 최종 확인 데이터를 분리한다.

매 실험은 설정·source hash·커밋·AC 상태·부하·시작/종료 시각·최신 시도 선택·제외 쌍·종료 시점까지 기록한다. **다른 seed를 독립성의 대체물로 쓰지 않고 시작 국면의 교집합을 실제로 검사한다.** 판정 이후 샤드의 추가 완료 대국은 별도 설명 통계로 남긴다.

## 6. 다른 후보

현재 fast 프로파일에서 materialize/legality와 경로 비용도 남아 있다. 후보 생성/합법성 메타데이터 재사용, 계측 분류에 rowMasks 항목 추가, 동일 국면의 계산 재사용을 우선 진단할 가치가 있다. 이득은 미측정이며 엔진 변경과 계측만의 변경을 분리한다.

순수 null-move pruning은 이번 우선순위에 넣지 않는다. 패스가 없는 쿼리도의 경주·벽 보존 상황에서 가정이 성립하는지 먼저 입증해야 한다. 깊은 TT 값 재사용·후보 수 확장·평가 함수 재학습도 결과가 바뀌는 별도 연구로 취급한다. 다인전·변형 대전은 이번 정규 2인전 연구 옵션에서 분리해 보존한다.
