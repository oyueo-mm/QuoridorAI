# 게임 모드와 규칙 해석

QuoridorAI의 모드는 **기본 대전**(공식 규칙)과 **변형 대전**(이 프로젝트의 커스텀 규칙)으로 나뉩니다. 신규 변형 6종은 모두 한 기기에서 사람끼리 두는 로컬 대국이며, AI는 붙지 않습니다.

| 모드 | id | 인원 | 구분 | 벽(기본) |
|---|---|---|---|---|
| 사람 vs AI / 사람 vs 사람 | `vs-ai` / `local-2p` | 2 | 공식 | 10 |
| 정규 4인전 | `four-player` | 4 | 공식 (Gigamic) | 5 |
| 동방향 2인 경주 | `race-2` | 2 | 변형 | 10 |
| 동방향 4인 경주 | `race-4` | 4 | 변형 | 5 |
| 3인 개인전 | `three-player` | 3 | 변형 | 5 |
| 2 vs 2 팀전 | `team-2v2` | 4 (2팀) | 변형 | 5 (개인별) |
| 비대칭 대전 | `asymmetric` | 2~4 | 변형 | 플레이어별 0~20 |
| 장애물 경주 | `obstacle` | 2~4 | 변형 | 2인 10 / 3·4인 5 |

## 규칙 객체 (`MultiRules`)

모든 모드는 같은 엔진(`src/engine/multi.ts`)을 쓰고, 모드의 차이는 **데이터**로만 표현합니다.

| 항목 | 필드 |
|---|---|
| 플레이어 수·시작 위치·목표선 | `players[].start`, `players[].goal` (행 또는 열) |
| 턴 순서 | `turnOrder` (좌석 번호의 순환 순서) |
| 시작 플레이어 | 상태 생성 시 `firstPlayer` |
| 초기 벽 개수 | 상태 생성 시 `wallsPerPlayer` (좌석별) |
| 팀 구성 | `teams[seat]` (없으면 개인전) |
| 초기 장애물 | `neutralWalls[]` (중립 벽, 누구의 벽도 아님) |
| 무작위 시드 / 프리셋 | `seed`, `preset` (기록용) |
| 모드 id | `mode` |

- **승리 판정**: 이동으로 자기 목표선에 닿은 좌석이 `winner`. 팀전이면 `winningSeats(state)`가 그 팀 전원을 돌려줍니다. 목표선을 공유하는 좌석이 여럿이어도(동방향 경주) 판정은 각 좌석의 목표선 하나만 보므로 같은 코드로 동작합니다.
- **경로 검증**: 벽을 놓을 때 *모든* 좌석(같은 팀·같은 목표선 포함)에 목표선까지의 경로가 남는지 확인합니다. 말은 장애물로 치지 않습니다.
- 새 변형은 `src/engine/variants.ts`에 규칙 상수(또는 생성 함수)를 더하고 `MultiGameMode`에 id를 넣으면 됩니다. 엔진·보드·기보 코드에 모드별 분기는 없습니다. 기보 가져오기만 `checkModeConsistency`로 "모드 라벨과 규칙이 맞는지"를 확인합니다.

## 모드별 상세

**동방향 2인 경주** — 말은 맨 아래 줄의 d1·f1(좌우 대칭)에서 출발해 위쪽 줄이 목표입니다. 두 출발점 모두 목표까지 8칸. 선공이 구조적으로 유리할 수 있어 시작 플레이어를 고르거나 무작위로 정할 수 있습니다.

**동방향 4인 경주** — b1·d1·f1·h1(열 인덱스 1, 3, 5, 7)에서 출발해 모두 위쪽 줄이 목표. 배치는 좌우 대칭(P1↔P4, P2↔P3)이고 모두 목표까지 8칸이지만, 바깥쪽(b·h)과 가운데(d·f) 말은 주변 공간이 달라 *완전히 같은 조건은 아닙니다*. 완전한 공정성을 주장하지 않고 시작 플레이어 선택으로 보정하도록 했습니다. 차례는 P1 → P2 → P3 → P4(왼쪽 말부터).

**3인 개인전** — 아래·왼쪽·위의 중앙에서 출발해 각자 반대편이 목표. 차례는 아래 → 왼쪽 → 위(시계 방향, 정규 4인전과 같은 방향). 오른쪽 변이 비어 있어 위치별 유불리가 있을 수 있으므로 변형 규칙으로 표시하고 시작 플레이어를 고르거나 무작위로 정합니다. 벽은 5개씩(공식 4인전 값을 따름 — 공식 3인 규칙은 없음).

**2 vs 2 팀전** — 정규 4인전 배치(아래 P1·왼쪽 P2·위 P3·오른쪽 P4). A팀은 P1·P3(아래·위), B팀은 P2·P4(왼쪽·오른쪽)이고 차례는 A → B → A → B. 각자 자기 출발선의 반대편이 목표이고, 팀원 누구든 먼저 도착하면 그 팀이 이깁니다. 팀원 말도 일반 말과 똑같이 같은 칸에 못 서고 점프·대각선 규칙의 대상입니다. 벽은 아군에게도 똑같이 작용합니다. 공동 벽 자원은 없고 벽은 개인별 5개입니다.

**비대칭 대전** — 플레이어별 시작 칸·목표선(위/아래/왼쪽/오른쪽 줄)·벽(0~20)과 차례 순서·시작 플레이어를 설정합니다. 검증 정책은 "고치지 않고 거부": 보드 밖 칸, 겹치는 시작 칸, 시작부터 자기 목표선 위인 말, 범위 밖 벽 개수는 시작할 수 없고 이유가 표시됩니다. 설정이 공정한 대국을 보장하지 않는다는 안내를 화면에 표시합니다.

**장애물 경주** — 시작 시 중립 벽이 놓입니다(어두운 돌 무늬로 플레이어 벽과 구분, 개수에 포함되지 않음). 배치는 정규 시작(2인: 아래/위, 3인: 아래/왼쪽/위, 4인: 사방). 프리셋은 벽 개수만이 아니라 *평균 우회 거리*(빈 보드 대비 늘어난 최단 거리)와 *좌석 간 거리 차*(공정성)의 목표 대역으로 정의됩니다.

| 프리셋 | 벽 수 | 평균 우회 | 거리 차 상한 (2인 / 3~4인) |
|---|---|---|---|
| 쉬움 | 4~6 | +1~3 | 2 / 4 |
| 보통 | 8~10 | +3~6 | 3 / 5 |
| 어려움 | 12~16 | +6~14 | 4 / 6 |
| 무작위 | 5~14 (시드로 결정) | 시드로 결정(±1.5) | 4 / 6 |

생성기는 시드 기반(mulberry32)으로 벽을 하나씩 더하며, 각 벽은 엔진의 겹침·경로 검사를 통과해야 합니다. 대역 안의 맵을 최대 60번 시도해 찾고, 못 찾으면 가장 가까운 후보를 씁니다(생성 결과는 항상 규칙 검증을 통과). 난이도 지표(`obstacleMetrics`)에는 *최단 경로의 가짓수*(대체 경로 수)도 포함되어 규칙 탭에 표시됩니다. 같은 `(인원, 프리셋, 시드)`는 항상 같은 맵입니다.

## 이동·점프 해석 (모든 다인 모드)

공식 룰북은 2인 점프를 설명하고 4인에서는 "다른 말도 상대로 취급"하는 정도로 확장합니다. 다음 조합은 룰북이 명시하지 않으므로, 이 프로젝트의 **해석**을 적용하고 테스트(`src/engine/__tests__/multiExceptions.test.ts`)로 고정했습니다. 공식 규칙이라고 단정하지 않습니다.

1. 인접한 말은 *하나만* 직선으로 뛰어넘을 수 있고, 바로 뒤 칸이 보드 안·벽 없음·비어 있음일 때만 가능합니다.
2. 직선 점프가 벽·보드 끝·**다른 말**에 막히면 뛰어넘은 말의 좌우 옆 칸으로 대각선 이동합니다(그 옆 칸에 벽이나 말이 있으면 제외).
3. 말이 둘 이상 일렬로 붙어 있어도 연속 점프는 없습니다. 첫 말 기준 대각선만 가능합니다.
4. 말과 말 사이에 벽이 있으면 점프할 수 없습니다.
5. 팀전의 팀원 말도 1~4가 똑같이 적용됩니다.
6. 벽 검사에서 말은 영구 장애물이 아닙니다(말은 비켜날 수 있음). 모든 좌석의 경로가 남아야 합니다.

## 기보 형식

- **버전 1**: 정규 2인전 (변경 없음, AI 비교·관전·실험이 읽음).
- **버전 2**: 정규 4인전 (변경 없음, 정규 4인전은 계속 버전 2로 저장).
- **버전 3** (신규): 변형 모드. 버전 2의 모든 필드에 더해 `rules.teams`, `rules.neutralWalls`(명시적 칸 — 재생이 생성기 버전에 의존하지 않음), `rules.seed`, `rules.preset`이 들어갑니다. 모드 id·참가자 이름·좌석별 시작 칸/목표선·턴 순서·좌석별 벽 개수·시작 플레이어·모든 수(플레이어 포함)·최종 포지션 체크섬을 담습니다.

가져오기는 모든 수를 엔진으로 재생하며 다음을 거부합니다: JSON 오류, 형식/버전/모드 불명, 규칙과 모드 라벨 불일치, 중복·보드 밖 시작 칸, 이미 도착한 초기 배치, 겹치거나 경로를 막는 중립 벽, 팀 정보 오류, 벽 개수 범위 밖, 불법 수·잘못된 차례, 최종 포지션 불일치. 거부되면 현재 게임은 그대로이고, 진행 중인 게임(수가 있는 게임)을 덮어쓸 때는 확인창이 뜨며 취소하면 그대로 유지됩니다. 가져온 뒤 "게임 재시작"은 가져온 시작 조건(장애물 맵 포함)을 그대로 다시 시작합니다.

## AI 호환 정책

기존 AI(Random·BFS·Minimax·MCTS·AlphaZero 학습 인프라)는 *정규 2인전만* 지원합니다. 신규 모드는 2인용 변형(동방향 경주 등)도 포함해 전부 사람 대전으로만 제공하며, 2인 AI로 가는 경로가 없습니다: 변형 모드는 `MultiController`(AI 없음)에서만 실행되고, `parseRecord`(AI 비교·관전·실험이 쓰는 파서)는 버전 2·3 기보를 이유와 함께 거부하며, `supportsTwoPlayerAi(rules)`는 모드가 지정된 규칙(`rules.mode`가 있는 규칙)을 항상 거부합니다.

### 다음 단계(다인전 AI·관전·실험)에 필요한 구조 변경

1. **AI 인터페이스**: `src/ai/multiAgent.ts`의 `MultiAgent`(규칙 지원 여부 선언 + `chooseAction(MultiState)`)를 구현하고, 에이전트 레지스트리를 2인용(`GameState`)과 다인용(`MultiState`)으로 분리합니다. 현재 `ai/*`는 `GameState`·`PlayerId = 0|1`에 묶여 있습니다.
2. **평가·탐색**: BFS 거리 휴리스틱을 "내 거리 vs 나머지 평균/최소"로 일반화하고, 탐색은 Max-N(또는 팀전은 팀 합산 Paranoid)부터 시작합니다. MCTS는 다인 롤아웃(좌석 순환)과 좌석별 보상 벡터가 필요합니다. 팀전은 보상을 팀 단위로 합산합니다.
3. **상태 인코딩**: `engine/encoding.ts`·`tensor.ts`(209개 행동, 2인 평면)는 2인 전용입니다. 다인 AlphaZero는 좌석 수 가변 입력 평면(목표선 방향, 팀, 중립 벽 평면, 좌석별 벽 개수)과 정책 헤드 정의를 새로 해야 합니다.
4. **Worker 프로토콜**: `ai/worker/*`가 `GameState`를 직렬화합니다. `MultiState`(규칙 포함) 직렬화와 요청 타입을 추가해야 합니다.
5. **관전·비교·실험**: `MatchSession`·`runMatch`·`tournament`가 2인 `GameState`/기보 v1을 전제합니다. 다인 대국은 `MultiController`에 에이전트 좌석을 붙이는 `MultiMatchSession`을 따로 두고, 기보 v2/v3를 `GameLine`의 일반화로 읽도록 해야 합니다. 자동 실험은 좌석 순환(Latin square)으로 선공 편향을 보정해야 합니다(경주 모드는 선공 이점이 큼).
6. **결정론**: 장애물 맵과 시작 플레이어는 이미 시드로 재현 가능합니다. AI 시드는 맵 시드와 분리해 기보에 기록하는 편이 좋습니다.
