# 다인전 AI — 브라우저 UI 반응성 (e2e/multi-ai.e2e.mjs)

측정 조건: 헤드리스 Chromium, Vite 개발 서버(미최소화 React), 1280×900, Intel Core Ultra 7 256V. 정규 4인전, **네 자리 모두 Max-N 어려움**(깊이≤8, 수당 3초 예산), 속도 "최대", 10초간 `requestAnimationFrame` 간격을 기록. 한 번 실행한 값이며 기계·부하에 따라 달라집니다.

| 실행 방식 | 프레임 수 / 10초 | p95 간격 | 최대 간격 | 10초 동안 둔 수 | "일시정지" 눌러 탐색이 멈췄다고 표시되기까지 |
|---|---:|---:|---:|---:|---:|
| Web Worker | 533 | 17.0 ms | 183 ms | 4 | 81 ms |
| 워커 없음 (메인 스레드 폴백, 80ms 예산 + 40ms 대기) | 193 | 199.6 ms | 267 ms | 55 | 336 ms |

- 워커에서는 탐색이 메인 스레드를 막지 않습니다. 100ms를 넘은 프레임은 10초 동안 2번(158~183ms)이었고 수가 반영되는 순간의 렌더링으로 보입니다(원인을 따로 분리해 측정하지는 않았습니다).
- 폴백은 탐색을 80ms로 줄이는 대신 매 결정 앞에 40ms를 비워 둡니다. 화면은 계속 갱신되지만 프레임 간격이 길어지고(p95 약 200ms), AI가 훨씬 약해집니다.
- 취소: 워커 경로는 `terminate()`라 즉시이고, 탐색 함수 자체도 취소 플래그를 노드마다 확인합니다(Node 벤치마크: 플래그를 올린 뒤 평균 0.3ms에 반환).
